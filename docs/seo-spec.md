# Stage 0 — техническая SEO-спецификация

Статус: спецификация для V1. Этот документ описывает требования к будущему сайту и его проверке; Stage 0 ограничен документацией.

## 1. Назначение сайта

Сайт — персональное портфолио SEO-специалиста. Основные направления: Technical SEO, Semantic Research, On-page SEO, Site Architecture и SEO Automation. Цель сайта — показывать реальные кейсы, исследования, методику работы и технические навыки.

## 2. URL и структура V1

Планируемые пути:

```text
/
/cases/
/cases/gasprofservice/
/cases/talisman-online/
/research/
/lab/
/about/
/contact/
/404.html
```

Для всех обычных страниц используется единый формат URL с завершающим `/`. `/404.html` — техническое исключение. Основной домен и протокол следует зафиксировать до настройки абсолютных canonical и sitemap. Внутренние ссылки должны сразу вести на выбранные основные URL, без промежуточных редиректов. Новые служебные и дублирующиеся URL без необходимости не создавать.

## 3. Rendering и HTML

Основной контент каждой страницы должен находиться в статически сгенерированном HTML. Архитектура, при которой основной контент появляется только после выполнения JavaScript или загрузки через API, не допускается. JavaScript следует использовать только там, где он действительно нужен для взаимодействия.

Разметка должна использовать подходящие по смыслу элементы `header`, `nav`, `main`, `article`, `section`, `footer`. На каждой индексируемой странице нужен один логический `h1`; структура заголовков должна последовательно раскрывать содержание: H1 → H2 → H3.

## 4. Индексация и canonical

Обычные публичные контентные страницы предназначены для `index, follow`. Отсутствующие URL должны возвращать реальный HTTP 404; 404 URL не считаются индексируемыми страницами, а содержимое `/404.html` не включается в индексируемый набор. Технические страницы, которые существуют и возвращают HTTP 200, должны использовать `noindex, follow`, если они не предназначены для поисковой выдачи. `robots.txt` не должен использоваться как замена `noindex`.

Каждая индексируемая страница должна иметь self-referencing canonical с абсолютным URL. Он должен в точности совпадать с выбранным основным URL страницы, включая протокол, хост, путь и правило завершающего `/`.

## 5. Metadata

Для каждой индексируемой страницы предусмотреть:

- уникальный и соответствующий содержимому `title`;
- `meta description`;
- canonical;
- директиву robots (`index, follow`);
- Open Graph metadata, соответствующие содержимому и основному URL;
- один логический H1.

## 6. Sitemap и robots.txt

Sitemap должен содержать только канонические индексируемые URL. Не включать в него `/404.html`, редиректы, `noindex`-страницы, дубликаты и служебные страницы. URL в sitemap должны совпадать с canonical соответствующих страниц.

Для V1 использовать простой `robots.txt` без ненужных запретов. В нём должна быть указана абсолютная ссылка на sitemap. `robots.txt` не использовать как замену запрету индексации для 404 или технических страниц.

## 7. Structured Data

Применять Schema.org только там, где тип и свойства соответствуют видимому содержимому страницы. Предварительное соответствие:

| Страница | Типы |
| --- | --- |
| Главная | `WebSite` |
| `/about/` | `ProfilePage`, `Person` |
| Статьи в `/research/` | `Article` |
| Внутренние страницы с реально отображаемыми breadcrumbs | `BreadcrumbList` |

Не добавлять фиктивные `Review`, `Rating` и другие неподтверждённые данные. Наличие типа в этой таблице не требует создавать разметку там, где соответствующего содержания ещё нет.

## 8. Изображения

Для значимых изображений указывать содержательный `alt`, `width` и `height`, а также использовать оптимизированный формат. Для декоративных изображений устанавливать `alt=""`. Размеры следует задавать так, чтобы место изображения было зарезервировано до загрузки.

## 9. Производительность и responsive

Минимальные ориентиры Core Web Vitals: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1. Архитектура должна стремиться к минимальному объёму JavaScript.

Контрольные ширины для будущей адаптивной проверки: 375, 430, 768, 1024, 1440 и 1920 px. Используется один responsive-сайт без отдельного мобильного домена.

## 10. Accessibility

Предусмотреть навигацию с клавиатуры, видимые состояния фокуса, достаточный контраст, корректные `alt` для изображений, связанные с полями формы `label` и семантический HTML.

## 11. QA и будущий CI

В дальнейшем CI должен проверять как минимум:

- битые внутренние ссылки и внутренние ссылки с ответом, отличным от HTTP 200;
- отсутствующие `title` и `meta description`;
- отсутствующий H1 и несколько H1 на одной странице;
- отсутствующий canonical и несовпадение canonical с основным URL;
- проблемы sitemap: неканонические, неиндексируемые, дублирующиеся или недоступные URL;
- внутренние ссылки, ведущие через редирект;
- изображения без `width` или `height`.

Проверять итоговый статический HTML и опубликованные URL; конкретные инструменты CI определяются на следующем этапе.

## 12. Достоверность данных

В production запрещено добавлять фиктивные SEO-результаты, статистику, рост трафика, количество ключевых слов, кластеров и любые другие показатели. Публиковать только подтверждённые данные из реальных исследований. Для кейсов и исследований сохранять проверяемый источник, период и методику каждого количественного утверждения до публикации.

## 13. Принцип разработки

SEO является частью архитектуры проекта с самого начала: URL, rendering, индексируемость, metadata, семантика, производительность и проверяемость закладываются при проектировании страниц, а не добавляются отдельным этапом после разработки.
