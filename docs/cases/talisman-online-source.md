## FINDING-001 — sitemap содержит дубли, non-200 и нефинальные URL

Status: confirmed  
Public: yes  
Priority: high for HTTP 500; medium for other sitemap issues  
Category: technical-seo / sitemap  
Checked: 2026-09-22

### Claim

Проверенный sitemap содержал повторные записи, URL с конечным ответом не 200 и URL, проходящие через редирект до конечной страницы. Это не означает, что каждая запись sitemap ошибочна.

### Source

Подробный аудит: разделы 2.1, 2.2, 5.3 и 7.1, финальное уточнение подсчёта sitemap; краткий аудит: блок «Sitemap содержит технические ошибки».

### Scope

Один sitemap на 22.09.2026: 93 записи `<loc>`, 88 уникальных URL. Пять URL были записаны по два раза. Финальный HTTP ответ проверен для всех 88 уникальных URL; fetch failures — 0.

### Evidence

- Sitemap: 93 entries = 88 unique URLs + 5 повторных вхождений. Повторены `/adults`, `/blog`, `/news`, `/kids/holidays`, `/kids/english/angliyskiy-dlya-detey-10-12-let/a2/`.
- HTTP: среди 88 уникальных URL — 84 с конечным HTTP 200, 3 с 404 (`/404`, `/adults`, `/kids`) и 1 с 500 (`/adults/master-classes`). Ответы оценивались после перехода к конечному URL; причина 500 не установлена.
- Redirects: 25 уникальных sitemap URL проходили через редирект до финального адреса. Это метрика sitemap, отдельная от внутренних ссылочных вхождений в FINDING-002.
- Manual check: `/404` и `/adults` перепроверены через `curl.exe` после ошибки раннего PowerShell-сканера; случайный несуществующий URL тоже дал реальный 404.

### Verification

Финальный полный прогон сверил sitemap entries, дедуплицированные URL и конечные HTTP ответы. Для спорных ранних HTTP 0 использована отдельная повторная проверка. Не складывать повторы sitemap с non-200 URL: категории могут пересекаться.

### Why it matters

В sitemap следует подавать финальные индексируемые страницы. 404 и 500 не являются такими страницами; повторы и редиректящие адреса ухудшают точность карты сайта.

### Recommendation

Убрать служебные и несуществующие URL либо восстановить нужные страницы, исправить HTTP 500 и заменить нефинальные адреса на канонические URL с прямым HTTP 200. После изменений пересобрать sitemap и проверить его заново.

### Limitations

Это снимок проверки 22.09.2026. Не установлены причина HTTP 500, последующие изменения sitemap или бизнес-назначение каждого устаревшего URL. Отдельный блок «Мастер классы» на другой странице не доказывает, что он официально заменил `/adults/master-classes`.

### Publication note

Можно использовать 93 / 88 / 5, распределение 84 / 3 / 1 и отдельное число 25 при сохранении единиц измерения, даты и примеров. Не писать «93 ошибочных URL».

## FINDING-002 — внутренние ссылки ведут через редиректы

Status: confirmed  
Public: yes  
Priority: medium  
Category: internal-linking  
Checked: 2026-09-22

### Claim

В проверенных страницах часть внутренних ссылок вела через промежуточные редиректы вместо прямого перехода к конечному HTTPS URL.

### Source

Подробный аудит: разделы 7 и 7.3; краткий аудит: блок «Много внутренних ссылок ведут через лишние редиректы».

### Scope

В HTML страниц из sitemap-crawl рассмотрены 4 940 внутренних ссылочных вхождений и 229 уникальных внутренних targets. Это не полный граф всех URL сайта.

### Evidence

- Internal links: 481 из 4 940 ссылочных вхождений вели через редирект. Они относились к 39 уникальным исходным redirect URL, а не к 481 уникальному адресу.
- Redirect chains: среди 39 URL зафиксированы 29 цепочек с 2 переходами, 9 с 3 и одна с 5. В части цепочек встречалась схема HTTPS без slash → HTTP со slash → HTTPS со slash; она не приписывается всем 39 URL.
- Example: для `/kids/podgotovka-k-ege` в аудите отмечена цепочка из 5 редиректов до конечной страницы курса.
- Separate population: 25 редиректящих sitemap URL относятся к FINDING-001, а не к знаменателю 4 940 ссылочных вхождений.

### Verification

Read-only crawl разрешал внутренние targets и фиксировал конечные URL и hops. Повторные ссылки на один redirect source считались вхождениями, а источники также подсчитаны после дедупликации.

### Why it matters

Внутренняя ссылка может сразу указывать на целевой URL и не заставлять браузер или crawler проходить лишние переходы. Найденный HTTPS → HTTP → HTTPS вариант требует проверки нормализации URL.

### Recommendation

Обновить ссылки в шаблонах на конечные HTTPS URL с согласованными host и trailing slash. После изменения повторно проверить ссылочные targets и цепочки.

### Limitations

481 — количество ссылочных вхождений, 39 — количество уникальных исходных redirect URL. Длина цепочки сама по себе не устанавливает конкретное серверное правило, создавшее её; влияние на трафик не измерялось.

### Publication note

Использовать числа вместе с их разными единицами и границей sitemap-crawl. Не превращать каждый hop или повторяющуюся ссылку в отдельную корневую SEO-проблему.

## FINDING-003 — canonical отсутствовал в HTML большинства final-200 страниц выборки

Status: confirmed  
Public: yes  
Priority: medium  
Category: canonical / indexability  
Checked: 2026-09-22

### Claim

Canonical отсутствовал в исходном HTML на 81 из 84 проверенных страниц с финальным HTTP 200.

### Source

Подробный аудит: разделы 5.3 и 7.4; краткий аудит: блок «Canonical отсутствует на большинстве страниц».

### Scope

84 уникальных URL из проверенного sitemap с конечным HTTP 200. Четыре URL с финальным 404/500 не входят в знаменатель.

### Evidence

- HTML: canonical найден на 3 из 84 финальных HTTP 200 страниц — `/blog/`, `/news/`, `/promotions/`; в исходном HTML остальных 81 canonical не найден.
- Earlier sample: предварительный проход первых 20 уникальных sitemap URL успешно получил 18 HTML-страниц с HTTP 200 и не нашёл на них canonical. Это часть исследовательского процесса, не дополнительный независимый знаменатель к 84.

### Verification

Массовый HTML-проход сопоставлен с конечным HTTP status. Для публичного вывода использовать финальный scope 81/84, а не предварительные 18/18 и не все 88 URL.

### Why it matters

Единая canonical-логика помогает явно обозначить основной адрес индексируемой страницы, особенно при нескольких вариантах URL и редиректах.

### Recommendation

Для финальных индексируемых страниц определить основной URL и добавить один соответствующий self-referencing canonical; затем проверить HTML и HTTP ответы после внедрения.

### Limitations

Проверка установила отсутствие тега в полученном исходном HTML. Она не исключила отдельно canonical через HTTP Link header или добавление после выполнения JavaScript. Нельзя писать «на всём сайте нет canonical» или делать вывод о фактической индексации.

### Publication note

Дословно сохранять «81 из 84 проверенных страниц с финальным HTTP 200» и дату. Рекомендация не является фактом внедрения.

## FINDING-004 — Schema.org использовала нефинальные URL и неверную ветку навигации

Status: confirmed  
Public: yes  
Priority: medium; mismatch детской навигации — high among schema findings  
Category: structured-data  
Checked: 2026-09-22

### Claim

В существующей разметке обнаружены четыре повторяющихся типа несогласованности: URL с HTTP вместо финального HTTPS, non-www Product URL вместо конечного www host и детские BreadcrumbList, не совпадающие с видимой навигацией.

### Source

Подробный аудит: раздел Structured Data / Schema.org, четыре подтверждённых типа; краткий аудит: блок о системных ошибках Schema.org.

### Scope

Read-only проверка server-response HTML 88 уникальных sitemap URL, без fetch failures. JSON-LD обнаружен на 55/88 URL; на остальных 33 не найдено обнаруживаемой JSON-LD, Microdata или RDFa разметки. Сам факт отсутствия разметки на этих страницах не считается ошибкой.

### Evidence

- BreadcrumbList: на 54 страницах `item` URL имели `http://www.talisman-online.ru/...` вместо конечного HTTPS; 162 URL-level occurrences относятся к повторению этого типа проблемы, а не к 162 независимым причинам.
- Product: на 54 страницах entity URL использовал `https://talisman-online.ru/...` без `www`; live-проверка показала переход non-www на www HTTPS.
- Детский BreadcrumbList: на 29 course pages второй ListItem указывал на `/adults/{language}/`, тогда как видимые хлебные крошки вели через `/kids/{language}/`. Это прямое несоответствие разметки и интерфейса.
- ItemList: на `/prices/` найдено 135 HTTP URL properties; 20 уникальных targets были live-проверены и редиректили на HTTPS 200. Это свойства одной страницы, не 135 страниц.
- Syntax control: malformed JSON-LD в полученном HTML не найден.

### Verification

Проверены типы и значения URL в извлечённой разметке. Для Product и контрольных ItemList targets конечные host/protocol сверены live; для детских BreadcrumbList сравнивались JSON-LD и видимые крошки. Четыре типа проблем отделены от количества строк URL-level выгрузки.

### Why it matters

Разметка должна описывать фактическую страницу и видимый путь пользователя, а URL сущностей могут сразу указывать на конечный адрес без редиректа.

### Recommendation

Исправить генераторы BreadcrumbList, Product и ItemList в соответствующих шаблонах; на детских страницах сверять разметку с видимыми крошками. Повторить выборочную проверку URL, final status и соответствия интерфейсу.

### Limitations

Проверка относится к fetched/server-response HTML и не описывает schema, возникающую только после клиентского взаимодействия. Отсутствие Course, Organization, Event, FAQPage или любого другого возможного типа не считается автоматической ошибкой; обязательность отдельного свойства здесь не устанавливалась.

### Publication note

Для публичного примера предпочесть наглядный mismatch `/adults/` против `/kids/`. Другие числа приводить только с их единицами: страницы, URL-level occurrences, свойства ItemList и уникальные live-проверенные targets.

## FINDING-006 — редакционный и on-page QA подтвердил отдельные ошибки

Status: confirmed  
Public: yes  
Priority: low for editorial examples  
Category: content / on-page  
Checked: 2026-09-22

### Claim

После автоматического поиска кандидатов и ручной перепроверки подтверждены отдельные ошибки в редакционном тексте и метаданных. Общий агрегат количества проблем для этой записи не используется.

### Source

Подробный аудит: разделы 5.1, 6 и 6.1 «Финальный live QA»; краткий аудит: блок текстовых и мета-ошибок. Финальный live QA имеет приоритет над ранними словарными срабатываниями.

### Scope

Отдельные проверенные фрагменты текста и metadata на live-страницах в рамках аудита от 22.09.2026. Это не подсчёт всех опечаток сайта. Тексты отзывов и скрытого DOM отделены от редакционных.

### Evidence

- Meta Description главной `https://www.talisman-online.ru/`: «французкого» вместо «французского»; проверено отдельно, потому что первоначальный spell-check видимого текста не анализировал meta description.
- Финальный live QA: «Заняти проходят» → «Занятия проходят» и «21 языковых центров» → «21 языковой центр» в Meta Description; «Курс егэ» → «Курс ЕГЭ» в Title. Точные URL этих отдельных примеров перед публикацией сверить с итоговой выгрузкой; здесь не приписывать им новые адреса.
- Видимый редакционный текст: «предложеный» → «предложенный» был зафиксирован на двух проверенных детских страницах английского.
- Rejected candidate: «отввечает» снято после ручной live-проверки — текущий видимый текст показывал корректное «отвечает». Скрытое `test` также не входит в подтверждённые видимые ошибки.

### Verification

Сигналы spell-check сверялись вручную с live-страницами и метатегами. Имена, бренды, допустимые формы, пользовательские отзывы и повтор одного шаблона не считались отдельными publisher-controlled ошибками автоматически.

### Why it matters

Ошибки в Title, Description и редакционном тексте ухудшают качество представления страницы; повторяющуюся формулировку выгоднее исправлять в её источнике, а не считать каждое вхождение независимой проблемой.

### Recommendation

Исправить подтверждённые фрагменты в соответствующих редакционных полях или шаблонах, затем повторно проверить исходный HTML и видимую страницу.

### Limitations

В подробном документе заявленный общий агрегат расходится с суммой приведённых групп severity. Ни этот агрегат, ни арифметическая сумма групп здесь не используются как доказанное число независимых проблем. Дата и точные URL каждого примера должны сопровождать будущую публикацию.

### Publication note

Показывать несколько конкретных примеров как один небольшой блок content QA. Не использовать снятые «отввечает» и скрытое `test` как подтверждённые ошибки; не перечислять пользовательские отзывы как ошибки редакции.

## CHECK-001 — HTTP 0 сканера перепроверен

Status: not-confirmed  
Public: yes  
Checked: 2026-09-22  
Category: technical-validation

### Hypothesis

HTTP 0 раннего PowerShell-сканера для `/404` и `/adults` мог ошибочно обозначать состояние страниц и породить ложные выводы о metadata.

### Scope

Два конкретных URL из раннего прохода, плюс случайный несуществующий URL как контроль soft 404.

### Limitation

Контроль касается этих URL и даты проверки; отсутствие soft 404 на случайном URL не доказывает отсутствие любых вариантов soft 404 на всём сайте.

### Publication note

Можно показать как пример повторной проверки сбоя инструмента другим способом.

## CHECK-003 — совпадения metadata после редиректов

Status: not-confirmed  
Public: yes  
Checked: 2026-09-22  
Category: metadata-validation

### Hypothesis

Группы одинаковых Title, Meta Description и H1 на разных исходных sitemap URL могли выглядеть как независимые дубли страниц.

### Scope

Полный прогон 88 уникальных sitemap URL нашёл по три группы одинаковых Title, Description и H1. В том же прогоне зафиксированы редиректы, в том числе `/franchise` → главная и `/kids/podgotovka-k-ege` → страница курса. Источник не связывает каждый из этих примеров с конкретной группой одинаковых метаданных и не перечисляет полный состав групп.

### Evidence

Подробный аудит, раздел 5.3: значительная часть совпадений возникла из-за исходных URL, ведущих на одну и ту же конечную страницу. Сравнивались Title, Meta Description и H1, а также конечные URL после переходов. Точных пар «исходный URL — группа metadata» в текстовом отчёте нет; не восстанавливать их догадкой.

### Result

Подозрение, что каждая группа автоматически означает отдельные страницы с дублирующимся контентом, не подтвердилось. Это не доказывает отсутствия любых настоящих дублей; перед отдельной претензией нужна дедупликация по финальному URL.

### Limitation

Нельзя приписывать `/franchise` или `/kids/podgotovka-k-ege` конкретной группе дублированных метаданных без итоговой построчной выгрузки.

### Publication note

Использовать как пример проверки знаменателя и конечного URL, а не как заявление «дублей Title нет».

## Quantitative evidence rules
