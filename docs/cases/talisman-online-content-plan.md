## Selected findings

Предложение для публичного кейса: **шесть** блоков. Каждый опирается на источник, но требует сверки разрешённых для публикации URL и фрагментов перед переносом в production Markdown. Никакая находка не доказывает эффект будущего исправления.

### 1. Non-200 и повторы в sitemap

- **Status:** confirmed для проверки от 22.09.2026.
- **Scope / evidence:** 93 записи, 88 уникальных URL, 5 повторённых URL; среди 88 конечных ответов — 3 HTTP 404 и 1 HTTP 500. В качестве проверяемых примеров — `/404`, `/adults`, `/kids`, `/adults/master-classes`; последняя страница отвечала 500. Полный список повторов и ответы должны оставаться доступны во внутреннем source record.
- **Почему важно:** sitemap подаёт поисковику служебные, несуществующие и временно неработающие адреса как страницы для обхода. Повторы засоряют список URL.
- **Recommendation:** убрать неактуальные URL или восстановить страницу; для устаревшего URL выбирать релевантную замену по фактической структуре; исправить 500 и пересобрать sitemap.
- **Limitation / числа:** разрешены 93/88/5 и 3×404 + 1×500 с датой и методом. Не утверждать причину 500 или что `/adults/master-classes` официально заменён внешним сайтом мероприятий.

### 2. Внутренние ссылки через многошаговые редиректы

- **Status:** confirmed для sitemap-crawl.
- **Scope / evidence:** из 4 940 внутренних ссылочных вхождений 481 вела через редирект; это 39 уникальных исходных redirect URL. Из них 29 цепочек с 2 hops, 9 с 3, одна с 5; в части цепочек отмечен промежуточный переход с HTTPS на HTTP-вариант со slash и обратно на HTTPS. В sitemap отдельно найдено 25 редиректящих URL.
- **Почему важно:** ссылки и sitemap могут вести сразу на конечный адрес без лишних запросов и неоднозначной нормализации URL.
- **Recommendation:** обновить шаблоны внутренних ссылок и генератор sitemap на финальные HTTPS + www URL с согласованным slash; затем перепроверить цепочки.
- **Limitation / числа:** разделять 481 вхождение, 39 уникальных источников и 25 sitemap URL. Длина цепочки не доказывает причину в конкретном серверном правиле. Назначение `/franchise` остаётся отдельной гипотезой.

### 3. Canonical в HTML финальных страниц

- **Status:** confirmed в полученном HTML.
- **Scope / evidence:** из 84 sitemap URL с конечным HTTP 200 только у 3 найден canonical; у 81 в исходном HTML его нет. Более ранняя проверка 20 URL дала 18 успешно полученных HTTP 200 страниц без canonical, но не является дополнительным независимым denominator к финальному прогону.
- **Почему важно:** для индексируемых страниц нужен согласованный основной URL, особенно при наличии редиректов и вариантов адресов.
- **Recommendation:** определить финальные индексируемые URL и внедрить единообразный self-referencing canonical; проверить HTML и конечный HTTP ответ после исправления.
- **Limitation / числа:** публиковать 81/84, не «на всём сайте». Перед общим выводом учесть возможный HTTP Link header или клиентское добавление; их отсутствие исходная HTML-проверка не доказывает.

### 4. Structured Data не соответствует видимой навигации и финальным URL

- **Status:** confirmed для четырёх шаблонных типов, описанных в отдельном инвентаре ниже.
- **Scope / evidence:** на 29 детских страницах BreadcrumbList использовал ветку `/adults/`, тогда как видимые крошки вели через `/kids/`. Дополнительно зафиксированы HTTP item URL в BreadcrumbList на 54 страницах, non-www Product URL на 54 страницах и HTTP URL properties в ItemList страницы `/prices/`.
- **Почему важно:** сущности разметки должны совпадать с видимым содержимым и указывать прямо на конечные адреса. Основным примером для читателя выбрать несоответствие детской навигации.
- **Recommendation:** исправлять генератор Schema.org в соответствующих шаблонах; сравнить видимые крошки, JSON-LD и финальные URL на контрольных страницах.
- **Limitation / числа:** можно использовать 29, 54 и 135 только с их разными совокупностями; 135 — свойства одного ItemList, не 135 страниц. Не объявлять отсутствие Course или Organization обязательной ошибкой.

### 5. On-page поля страницы `/gift`

- **Status:** confirmed в проверенном HTML.
- **Scope / evidence:** одна страница `/gift` ответила HTTP 200 и имела Title, но без Meta Description, H1 и canonical. URL и исходный HTML — основной материал для будущего source record.
- **Почему важно:** пользовательская страница не получила базовую структуру заголовка и метаданные; canonical также входит в общую находку выше.
- **Recommendation:** добавить содержательные Description и H1, определить canonical по финальному URL; проверить страницу после изменений.
- **Limitation / числа:** это наблюдение об одной странице, не вывод о шаблоне всех посадочных. Предположение о её «сиротстве» сюда не включать: ноль inlinks получен только в пределах sitemap-crawl.

### 6. On-page и редакционный QA после ручной фильтрации

- **Status:** confirmed для отдельных видимых/мета-примеров; агрегат 16 — needs-recheck.
- **Scope / evidence:** в Meta Description главной зафиксировано «французкого» вместо «французского»; финальная проверка также приводит «Заняти проходят» и «21 языковых центров» в метаданных, «Курс егэ» в Title. Редакторский блок «Рекомендовано от 2 раз в неделю» повторялся в проверенной выборке. Для публикации выбрать несколько точных URL и фрагментов из финального live QA.
- **Почему важно:** проверка метаданных и редакционных шаблонов дополняет технический crawl; повторяющийся текст следует исправлять в источнике, не считать его десятками независимых проблем.
- **Recommendation:** исправить подтверждённые тексты в соответствующих шаблонах и метатегах, затем повторно проверить видимые страницы и исходный HTML.
- **Limitation / числа:** не публиковать «16 ошибок», пока не устранено противоречие с суммой severity. Не приписывать сайту ошибки из пользовательских отзывов и скрытого DOM. Отдельные опечатки не превращать в шесть самостоятельных крупных findings.

## Proposed control checks

Для публичного блока выбрать не больше трёх коротких примеров; подробные команды и логи оставить во внутреннем source record.

1. **Настоящий HTTP 404, а не soft 404.** Ранний PowerShell-сканер записал HTTP 0 для `/404` и `/adults` из-за ошибки получения ответа. Повторная проверка через `curl.exe` установила HTTP 404; случайный несуществующий URL тоже ответил 404. Поля metadata из неудачного сканирования не использовать.
2. **Скрытая строка `test` не стала видимой контентной ошибкой.** Ранний raw-HTML разбор дал 87 срабатываний, но финальная проверка DOM/CSS, видимого текста и accessibility tree показала скрытый блок. Не представлять эти 87 как пользовательские ошибки.
3. **Совпадения Title/Description/H1 после редиректов.** Первичный сканер нашёл по три группы одинаковых значений, но часть URL ведёт на одну конечную страницу. Без дедупликации по финальному URL это не доказательство независимых дублей контента.

Дополнительно: в проверенных sitemap URL не найдено конфликтов `noindex` / `nofollow` / X-Robots-Tag, а malformed JSON-LD не обнаружен. Эти результаты не доказывают фактическую индексацию в поисковых системах.

- Длинные Title и Description по внутренним порогам 65/180 символов — кандидаты на редакционный анализ, не нарушения официального лимита.
- URL `a1pluc` / `b1pluc` не переименовывать по одному лишь виду slug; сначала изучить индексацию, ссылки и риск смены URL.
- Ошибки в пользовательских отзывах не смешивать с publisher-controlled контентом; каждый текстовый пример проверять в контексте. Не переносить данные вакансии, сопроводительной переписки и внутренние комментарии.
- Отсутствие Course, FAQPage, Event, Organization и других возможных Schema.org типов само по себе не считать дефектом. Не добавлять фиктивные Review/Rating или иные сущности.
- Не переносить весь рабочий документ, приватные ссылки, исходные выгрузки, неразрешённые screenshots, неподтверждённые причины и KPI.

Для количественных заявлений сохранить отдельно 93 sitemap entries, 88 уникальных URL, 25 редиректящих sitemap URL, 481 ссылочное вхождение и 39 уникальных исходных redirect URL. Для canonical знаменатель — 84 финальных HTTP 200, а не все 88. Для Schema.org не смешивать число страниц, свойств JSON-LD, уникальных targets и корневых типов проблем. ## Claims that must not be made

- «SEO-работа увеличила трафик, позиции, заявки, продажи или конверсии»: внедрение и последующее измерение не подтверждены.
- «Все страницы сайта проверены» или «ошибка есть на всём сайте»: исходный crawl основан на URL sitemap и отдельно ограниченных выборках.
- «Сайт отдаёт soft 404», «87 видимых ошибок `test`», «все одинаковые метатеги — дубли контента», «`/prices/` и `/gift/` доказанно сиротские» — проверки этого не подтверждают.
- «Отсутствующий тип Schema.org всегда ошибка» или «138 независимых ошибок разметки»: это неверная интерпретация состава данных.
- «Известна причина HTTP 500, редиректов или поведения CMS» и «рекомендации внедрены»: этих подтверждений нет.

## Limitations

Аудит охватывал публично доступную версию сайта на 22.09.2026. Проверены 88 уникальных URL из sitemap; обход внутренних ссылок ограничен страницами этой совокупности и не равен полному crawl всего сайта. Часть вопросов решалась отдельными выборками или ручными контрольными проверками. Полученный server-response HTML не исключает разметку, появляющуюся после клиентского взаимодействия. Не подтверждены фактическая индексация, причины ряда серверных ответов, внедрение рекомендаций и измерения после него. При подготовке публичного Work Sample датировать наблюдения и не выдавать историческое состояние за текущее.
