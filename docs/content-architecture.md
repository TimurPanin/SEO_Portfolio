# Stage 3A — контентная архитектура SEO-портфолио

Статус: спецификация форматов контента. На этом этапе не публикуются реальные материалы и не меняются страницы сайта.

## 1. Типы контента

| Тип | Назначение |
| --- | --- |
| Case / Work Sample | Реальная выполненная SEO-работа: аудит, исследование проекта или другая работа с проверяемыми материалами. |
| Research | Техническое SEO-исследование отдельной проблемы. |
| SEO Lab | Инструменты, автоматизация и эксперименты. |

### Work Sample и Case Study

- **Work Sample:** работа или аудит выполнены; рекомендации могут быть не внедрены. Нельзя приписывать себе рост трафика или другие результаты без доказательств.
- **Case Study:** изменения действительно внедрены, а результат измерялся. Подтверждённые показатели можно показывать с указанием периода и источника данных.

Результаты нельзя придумывать ради оформления кейса. Рекомендации и факт их внедрения должны быть различимы.

## 2. Структура Case / Work Sample

Разделы идут в следующем порядке. Если подтверждённого результата нет, раздел «Результаты» не заполняется вымышленными показателями.

1. Overview
2. Задача
3. Контекст проекта
4. Scope / что проверялось
5. Методика
6. Инструменты
7. Найденные проблемы
8. Evidence / доказательства
9. Приоритеты
10. Рекомендации
11. Deliverables
12. Статус внедрения
13. Результаты — только если они реально существуют
14. Ограничения / что не проверялось

### Overview

Допустимые поля:

- название проекта;
- URL сайта, если его можно публично указывать;
- тип проекта;
- отрасль;
- CMS / технологии — только если подтверждено;
- регион;
- тип работы;
- дата или период исследования;
- статус: Work Sample / Case Study.

Поля опциональны, если сведения неизвестны или не должны публиковаться. Отсутствующее значение не заменяется догадкой.

### Evidence и количественные данные

Существенные утверждения по возможности подтверждаются URL, HTTP status, HTML или metadata, screenshot, экспортом SEO-инструмента, таблицей, результатом crawler, исходным документом и датой проверки. Для конкретного утверждения выбираются относящиеся к нему доказательства; чувствительные и приватные данные не публикуются.

Для количества URL, ошибок и запросов, позиций, трафика, конверсий и других чисел нужно хранить или указывать источник, дату либо период и методику подсчёта. Неподтверждённые декоративные цифры не используются.

### Условные разделы для Semantic Research

Если работа посвящена семантическому ядру, предусматриваются: источники запросов, raw keyword collection, очистка, кластеризация, search intent, keyword mapping, landing pages, site architecture и deliverables. Эти разделы не обязательны для обычного Technical SEO кейса.

## 3. Структура Research

Для технического SEO-исследования отдельной проблемы используется более короткий порядок:

1. Проблема
2. Гипотеза
3. Методика
4. Данные
5. Наблюдения
6. Вывод
7. Ограничения
8. Рекомендации

Гипотеза не выдаётся за доказанный факт. Вывод опирается на представленные данные и учитывает ограничения исследования.

## 4. Структура SEO Lab

Для инструмента, автоматизации или эксперимента:

1. Проблема
2. Назначение
3. Что делает
4. Входные данные
5. Выходные данные
6. Ограничения
7. Source code / GitHub — если доступны публично
8. Пример использования

## 5. Роли страниц

### Главная `/`

Главная не дублирует полные кейсы. Она показывает краткое позиционирование, selected work, направления работы, инструменты, последние исследования и ссылки на подробные страницы.

### Индекс кейсов `/cases/`

Раздел показывает карточки работ. Карточка может содержать название, тип работы, краткое описание, статус Work Sample / Case Study, категорию и ссылку на подробную страницу. Выдуманные KPI в карточках не используются.

### Индекс исследований `/research/`

Раздел показывает реальные исследования и технические разборы.

### SEO Lab `/lab/`

Раздел пока может оставаться заготовкой. Инструменты, которых ещё нет, не придумываются.

## 6. Достоверность и публикация

- Факты отделяются от предположений, рекомендации — от результатов.
- Нельзя утверждать, что клиент внедрил рекомендации, если подтверждения нет.
- Не используются fabricated testimonials, fabricated traffic/position growth и другие вымышленные достижения.
- Не публикуются секреты, персональные данные и закрытые клиентские данные.

## 7. Будущее хранение контента

Позже материалы можно хранить в Astro Content Collections или другом структурированном формате. Этот документ описывает контентные поля и порядок разделов, не задавая текущую реализацию хранения. На Stage 3A не добавляются Content Collections, schema, Markdown/MDX кейсы или UI.
